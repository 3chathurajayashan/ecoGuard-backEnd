# EcoGuard Backend API Documentation

This is the backend implementation for the **"Ranger Reports Conservation Incident"** Use Case Scenario, developed as part of the SE3070 – Case Studies in Software Engineering module.

## Setup & Testing Instructions

1. **Install Dependencies:** `npm install`
2. **Environment Variables:** Update the `.env` file with your MongoDB URI and Cloudinary credentials.
3. **Run Server:** `npm start` (Runs on port 5001 by default).
4. **Run Unit Tests:** 
   To execute the test suite (testing all Main and Alternative flows in isolation):
   ```bash
   npm test
   ```
5. **View Test Coverage Report:** 
   To generate a detailed code coverage report showing exactly how much of the system is covered by tests:
   ```bash
   npm run test:coverage
   ```
   *(Note: The backend achieves >80% test coverage for all core business logic and notification services.)*

## 1. Incident Endpoints (Ranger Use Case)
*Base URL: `http://localhost:5001/api/incidents`*

### Public Routes (No Auth Required)
| Method | Endpoint | Description | Use Case Mapping |
| :--- | :--- | :--- | :--- |
| **GET** | `/types` | Get valid incident types and severity levels to populate the mobile app dropdowns. | **Main Flow Step 4** |

### Authenticated Ranger Routes (Requires Bearer Token)
| Method | Endpoint | Description | Use Case Mapping |
| :--- | :--- | :--- | :--- |
| **POST** | `/` | Create a new incident report. Accepts `multipart/form-data` for file uploads (photos/videos). | **Main Flow Steps 11-15** |
| **POST** | `/sync` | Batch synchronize locally-stored incidents when network connectivity becomes available. Accepts raw JSON. | **Alternative Flow A1** (No Network) |
| **PUT** | `/:id` | Update incident details (e.g. description, location) before or after submission. | **Alternative Flow A5** (Correct Details) |
| **POST** | `/:id/evidence` | Add additional photo/video evidence to an existing incident. Accepts `multipart/form-data`. | **Alternative Flow A3** (Evidence Management) |
| **DELETE** | `/:id/evidence/:evidenceId` | Delete a specific attached photograph or video. | **Alternative Flow A3** (Evidence Management) |
| **GET** | `/my-reports` | Retrieve a paginated list of all incidents reported by the logged-in Ranger. | - |

## 2. Notification Endpoints
*Base URL: `http://localhost:5001/api/notifications`*

*These routes are used by Park Management staff to view alerts generated by Main Flow Step 15 ("System notifies authorized park management staff").*

| Method | Endpoint | Description | Auth Requirement |
| :--- | :--- | :--- | :--- |
| **GET** | `/` | Get a list of notifications assigned to the user's role. | Management Roles Only |
| **PATCH**| `/:id/read` | Mark a specific notification as read. | Management Roles Only |

## Technical Details & Patterns Used
* **MVC Architecture:** Clean separation of Routes, Controllers, Services, and Models.
* **Offline-First Support:** Utilizes `clientId` deduplication and batch syncing endpoints to fulfill the A1 alternative flow.
* **Media Management:** Direct integration with Cloudinary via `multer-storage-cloudinary` to handle image and video evidence (Flow A3).
* **Validation & Error Handling:** Strict Mongoose schemas and a centralized error handling middleware to translate database errors into clean API responses.
